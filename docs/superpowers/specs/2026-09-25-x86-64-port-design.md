# x86_64 Port (Q35 + OVMF) — Design

Date: 2026-09-25. Status: design approved (S1–S4 in chat), awaiting spec review.
Goal: second arch target for the v2 microkernel with full parity to the
RISC-V build, same UABI numbers/semantics, same 44-marker QEMU smoke.

Non-goals: binary compatibility between rv64 and x86_64 ELFs (recompile,
not run-across); SMP (hart0-only discipline carries over as BSP-only);
CHERI-purecap userspace on x86_64 (hybrid discipline only); new syscalls.

## 1. Architecture / tree / build

The current `kernel/kboot.c` (2152 lines, arch inline) is split into a
shared core plus two backends behind `kernel/arch/hal.h`. Scheduler,
IPC queues (`kernel/ipc.h`), caps (`kernel/caps.h`), qube policy
(`kernel/qube.h`), ELF loader (`kernel/elf.c`), initrd (`kernel/initrd.c`
+ generated `kernel/initrd_data.c`), frame pool, and the `kernel/user.c`
demo threads stay shared and behavior-identical. Only the trap, paging,
console, timer, IRQ, and device-discovery layers differ per arch.

New layout:

- `kernel/core/` — arch-independent slices moved out of `kboot.c`
  (`sched.c`, `ipc_core.c`, `caps_core.c`, `qube_core.c`, `elf.c`,
  `initrd.c`, `frames.c`, `demo.c` from `user.c` logic). No CSR, no
  `ecall`/`syscall`, no MMIO/PIO addresses here (grep-gated).
- `kernel/arch/riscv/` — current code moved verbatim: `start.S`,
  `trap.S`, `sbi.c`, `sv39.c`, `plic.c`, `virtio_mmio.c`. Default build
  output (`kernel/build/moonlight.elf`) is byte-identical to today.
- `kernel/arch/x86_64/` — new backend: `uefi_entry.c` (OVMF entry,
  `ExitBootServices`, memory-map capture, PML4 build, jump to
  `kboot_main`), `boot64.S` (BSP check, BSS clear, GDT load, jump),
  `gdt.c`/`tss.c` (ring0/ring3 segments, IST trap stack), `idt.S` +
  `idt.c` (vectors, fault-containment entries, LAPIC-timer vector,
  EOI), `syscall_entry.S` (`syscall`/`sysret`, MSR setup: LSTAR/STAR/
  SFMASK/FMASK + EFER.SCE), `paging.c` (PML4, U/S bit, W^X, SMAP
  windows), `console.c` (COM1 `0x3F8` polled), `lapic.c` (TSC deadline
  + one-shot 100ms, arm-before-enable), `ioapic.c` (routes + EOI),
  `pci.c` (config-space enum, virtio-pci BAR leaves, IRQ routing),
  `linker.ld` (`OUTPUT_ARCH(i386:x86-64)`, kernel high
  `0xFFFFFFFF80200000`).
- `kernel/arch/hal.h` — the only surface `core/` may call:
  `hal_putc`, `hal_set_timer`/`hal_now`, `hal_paging_init`/
  `hal_map_leaf`/`hal_unmap_leaf`, `hal_trap_init`, `hal_irq_claim`/
  `hal_irq_enable`, `hal_pci_bar_map`, `hal_park`. Both backends
  implement it; `core/` holds no arch `#ifdef`.

Build:

- `kernel/Makefile` gains `ARCH=riscv64|x86_64` (default `riscv64`,
  current flags and output unchanged). `ARCH=x86_64` uses
  `clang --target=x86_64-unknown-elf -mno-red-zone -mcmodel=kernel
  -ffreestanding -nostdlib -fno-builtin -Wall -Wextra -Werror`,
  `lld -T arch/x86_64/linker.ld`, output
  `kernel/build/moonlight-x86_64.elf` plus `BOOTX64.EFI` loader.
- U window stays `0x80800000` on both arches so ELF-loader vpn math
  (`vpn = (p_vaddr - BASE) >> 12`, 32 slots) is unchanged.
  `userspace/v2_user.ld.x86_64` equals `v2_user.ld` except
  `OUTPUT_ARCH(i386:x86-64)`. `userspace/Makefile` gains
  `CFLAGS_X86_64 = --target=x86_64-unknown-elf -mno-red-zone
  -ffreestanding -nostdlib`; all ten ELFs build per arch from the same
  sources plus `v2_start_x86_64.S` entry and `syscall`-based stubs.
- Run: new `tools/run_qemu_x86_64.sh` —
  `qemu-system-x86_64 -M q35 -bios OVMF_CODE.fd -drive
  file=bootx64.fat,format=raw,if=none,id=esp -device
  usb-storage,drive=esp` (or `-kernel` multiboot2 if the OVMF build
  accepts fw_cfg delivery; the script probes and prefers the FAT path),
  `-device virtio-net-pci,netdev=n0 -netdev user,id=n0 -device
  virtio-blk-pci,drive=hd0`, `-serial mon:stdio -no-reboot`.
  `tools/build_ovmf_img.sh` packs `BOOTX64.EFI` + kernel ELF.
- `tools/verify.sh` builds both arches (`make -C kernel`,
  `make -C kernel ARCH=x86_64`) and runs both smokes against the same
  marker list (new `[4/4]x86` stage mirroring `[4/4]`).

## 2. Traps / syscalls / paging / interrupts

Trap model: IDT replaces `stvec`; vectors cover `#PF`/`#GP` (fault
containment — park offender, keep the other thread running, same demo
shape as the `cause=2` leg), `#UD`, LAPIC-timer (preempt), and spurious.
TSS/IST provides the trap stack; `syscall_entry.S` swaps
`GS:kernel_stack` exactly where `trap.S` swaps `sscratch`, then saves
in place into `cur_ctx` (regs layout widened to the x86_64 GPR set;
the C handler struct gains an x86_64 variant, handler logic shared).
`sret` becomes `sysret`/`iretq` per path; `SPP/SPIE` handling becomes
`CPL3` return-context construction (`SS:RSP/RFLAGS/CS:RIP`).

Syscall encoding (numbers and semantics identical, wires differ):

- RISC-V today: `ecall`, `a7=sys (0..7)`, `a0=ep/cap`, `a1=buf`,
  `a2=len`, `a3=aux`.
- x86_64: `syscall`, `rax=sys`, `rdi=ep/cap`, `rsi=buf`, `rdx=len`,
  `r10=aux`; returns `rax=nw`, `rsi=sender`, `rdx=qube`, `r10=ovf`
  (the `RECV` 4-word stamp). `rcx`/`r11` are clobbered by hardware and
  never carry data. The C handler signature above the entry stub is
  unchanged, so `core/` never sees registers. `V2_INVOKE` ops
  (`V2_INV_MAP 3` … `V2_INV_SPAWN 9`, `FORK 10`, `EXEC 11`, `WRITE 12`,
  `READ 13`, `QCREATE 14`, `QDESTROY 15`) and `V2_INV_*` reserved-args-
  zero rule carry over verbatim. Per-thread endpoints (`V2_NEP 10`,
  own-EP rule, `ep != cur → V2_ERR_INVALID` before any queue touch)
  carry over verbatim.

Paging: Sv39 3-level (root/l1/l0, U-bit) maps to PML4 4-level
(PML4/PDPT/PD/PT, U/S bit). Same split (kernel U/S=0, user U/S=1),
same per-thread tables sized to `V2_CAP_THREADS`
(`pml4_t/pdpt_t/pd_t/pt_u_t`, `NTHREADS 10` static bound kept with the
same `_Static_assert`), same W^X split (RX text/rodata, RW data/bss/
stacks), same shared kernel/frame leaves, same per-tid device leaves
(see S3). `SUM`-windowed `copy_from/to_user` (validate-then-copy)
becomes `SMAP`-windowed (`stac` around the bounded copy, `clac`
after); raw dereference of a user pointer outside those windows is a
CI grep failure on both arches.

Console/timer/IRQ: SBI `PUTCHAR` becomes COM1 `0x3F8` polled putc
(bring-up path only; the console-server direction from the roadmap is
unchanged). SBI `SET_TIMER` + `rdtime` becomes LAPIC one-shot + TSC
deadline (100ms tick preserved; arm-before-enable order preserved per
the stale-timer lesson). PLIC enable/threshold/claim (M+S contexts)
becomes IOAPIC route + LAPIC EOI; the same notify bits
(`NET_IRQ_BIT 0x1`, `BLK_IRQ_BIT 0x2`) flow into the same handler
paths. `wfi` park becomes `hlt` park (`sti; hlt` loop with the same
`no runnable left; parking cpu` marker).

Error handling is fail-closed on both arches with identical markers:
bad segment, unaligned ELF LOAD, oversized span, occupied grant dst,
wrong-qube access, leaked BAR leaf, or reserved-arg nonzero returns
`V2_ERR_INVALID`/`V2_ERR_OVERFLOW` (or silent drop for the
spoof-class, same as the net stub) and parks the offender; a missing
marker flips the smoke gate to FAIL. No stub ever impersonates a
server marker.

## 3. virtio-PCI + userspace ELFs

Q35 exposes virtio as PCI, not MMIO. The demo packet plane and block
path keep their message flow; only the transport changes.

Kernel `pci.c`: enumerates PCI config space (bus 0–255, slots 0–31),
matches virtio-net (`0x1AF4:0x1000`, modern transitional `0x1041`
accepted with the same fail-closed mismatch drop) and virtio-blk
(`0x1AF4:0x1001` / `0x1042`), records BAR0 (MMIO) + IRQ routing, and
maps BAR pages through per-tid leaves only: `pt_pcibar_net` wired for
tid 6, `pt_pcibar_blk` for tid 9; every other thread's leaf stays 0
with the same boot assert and the same markers (`NETMMIO: tid=6 only`,
`BLKMMIO: tid=9 only`, `[demo] FAIL` + park on leak). IRQ discovery
scans all devices (no slot-0 assumption, same discipline as today's
8-transport scan); `net_virtio_irq`/`blk_virtio_irq` become PCI IRQ
numbers (INTx via IOAPIC, or MSI-X vector where the QEMU build offers
it — the handler claims both paths like today's M+S PLIC fallback).

Userspace `net`/`cryptblk` ELFs: the virtqueue core (descriptor ring,
avail/used, `fw_decide` call in the firewall, FNV-1a hash recheck,
sector AEAD in cryptblk) is shared; a transport-ops table selects
`mmio_*` (RISC-V build) vs `pci_bar_*` + queue-notify BAR offset
(x86_64 build) at probe time. All policy is unchanged: firewall
single-flight pipeline (MAP scratch → `fw_decide` → ALLOW grants R +
`SEND T_FWD`, ASK/DENY unmap + `FW: deny`, `T_DONE` closes audit),
net grant chain (sender_qube==4, slot/len bounds, MAP, hash recheck,
silent drop on mismatch/spoof/grant-without-announcement),
cryptblk sector AEAD + `/dev/blk0` ciphertext vs `/` plaintext views,
vault `T_KEY 8` one-time handoff by GRANT to slot 20 + `T_KEY_ACK 10`
with tick-bounded ack-wait (park + REVOKE + wipe on expiry).
`qrexec`/`adminvm`/`vault`/`mem_server`/`firewall`/`moonsh`/`ls`/`cat`
recompile only (new `v2_start_x86_64.S`: set up stack, call `*_main`,
`syscall V2_PARK` loop). Initrd order 0–9, thread/qube numbering
(0 A … 9 cryptblk), `svc_of_qube`/`rpc_svc` tables, `ADMIN_LIVE_BIT 2`
handshake, and thread-A live ask (`VAULT: live ok`) + deny
(`AUD: deny rpc=2`) legs are identical.

## 4. Verification / rollout

Host unit tests are arch-independent and run unchanged
(`test_v2ipc/caps/qlabels/qube_policy/qargs/netfw/aead/crypt`,
libc batches, driver host-sims). Additions: cross
`_Static_assert(sizeof(uintptr_t)==8)` for
`--target=x86_64-unknown-elf` next to the existing rv64 one.

Production gates run per arch: linker gate (no PROGBITS in
`[_bss,_bss_end)`, per `linker.ld`), `user.c` rodata ban compiled for
both targets, plus a new HAL grep gate — `core/` must not reference
`satp/stvec/scause/sepc/ecall/sum` or `cr3/idt/iret/syscall/stac`
directly, and no raw user-pointer dereference outside
`copy_from/to_user`. `verify.sh` `[1e]` builds userspace per arch;
`[1f]` builds both kernels; `[4/4]` (RISC-V) and `[4/4]x86` assert the
same 44 markers (`satp Sv39 on` has an x86_64 sibling marker
`pml4 4-level on`; all other markers byte-identical).

Proofs and docs honesty: `V2_A` (scheduler), `V2_C` (IPC, incl.
endpoint-indexed separation), `V2_D` (caps), `Qubes_A/B/C/D` model
transitions over abstract state, not CSRs — they carry over untouched
and keep gating CI. `V2_B` (modes M/S/U, `satp`, SBI, PMP note) is
RISC-V-specific; the x86_64 companion (`V2_Bx86`: CPL0/CPL3, PML4 U/S,
COM1/LAPIC/IOAPIC/PCI-BAR isolation) is explicitly future work and
must not be claimed until built. `V2_DESIGN.md`, `BUILD.md`,
`ARCHITECTURE.md` gain x86_64 sections marked BUILT only when the
x86_64 44/44 smoke passes in CI.

Rollout (staged delivery inside the full-parity goal): M1 boot +
paging + serial (OVMF → `kboot_main`, `pml4 4-level on`,
`entering U-mode`); M2 traps + timer + sched (2-thread `A0..4` / `B`
/ fault-contain / clean park); M3 IPC + caps + ELF + initrd
(ping-pong `B00pn`/`A10pg`/`W1`, `MEM-SRV`, MEM/CAP/OK/DU/NP); M4
qubes + net + FDE + live legs (full 44/44 on `qemu-system-x86_64`,
then both QEMUs green). Each milestone extends `verify.sh` fail-
closed: a missing marker is FAIL, never SKIP.
