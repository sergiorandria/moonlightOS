# ELF Execution Implementation for MoonlightOS

## Overview

Enables running arbitrary ELF programs (bash, shells, utilities) in MoonlightOS through kernel-provided SPAWN/FORK/EXEC syscalls, with userspace command discovery and program launcher API.

## Architecture

### Kernel Layer (Already Implemented ✅)

The kernel (`kernel/kboot.c`) provides three V2_INVOKE syscalls for process control:

#### 1. V2_INV_SPAWN (syscall 9)
- **Purpose**: Create new thread and load initrd ELF
- **Input**: a1 = initrd index (e.g., 0 for mem_server.elf)
- **Output**: a0 = child tid (>= 0 on success, negative on error)
- **Semantics**:
  - Find a free T_DEAD thread slot (reuse mechanism)
  - Build child's VSpace (page tables, shared kernel/frames, own user window)
  - Load ELF from initrd (validation → frame allocation → byte copy → PTE install)
  - Set sepc = ELF entry point, state = T_RUNNABLE
  - Return child tid to parent

**All-or-nothing**: Any validation error (bad ELF, allocation failure, page table full) rolls back all frames and mappings. No half-loaded state.

#### 2. V2_INV_FORK (syscall 10)
- **Purpose**: Duplicate current thread's VSpace (Copy-on-Write)
- **Input**: None (no arguments)
- **Output**: a0 = child tid (parent), 0 (child); negative on error
- **Semantics**:
  - Find free thread slot
  - Copy parent's capability table (child gets same caps, root bits cleared)
  - Copy parent's mappings (both point to same frames initially)
  - Build child's VSpace
  - Apply COW write protection (drop PTE_W from both parent and child for W-mappings)
  - Copy parent's registers (including sp, a0-a7)
  - Set child's a0 = 0, a1 = parent_tid (fork return values)
  - Return parent's a0 = child_tid

**Fault Handler**: When either parent or child writes to a COW page, the fault handler allocates a new frame, copies content, updates the faulting thread's mapping to the new frame, and resumes. COW break is per-thread; both sides retain W rights in the capability model, but only one gets PTE_W restored.

#### 3. V2_INV_EXEC (syscall 11)
- **Purpose**: Replace current thread's image (execve-like)
- **Input**: a1 = initrd index
- **Output**: a0 = 0 (success, never returns on success); -1 on error
- **Semantics**:
  - Unmap all user VPN mappings
  - Free frames back to pool
  - Clear user capabilities (non-root only; root caps survive)
  - Load new ELF into same thread
  - Set sepc = entry, regs[2] = stack pointer, other regs zeroed
  - If successful: never returns (new image takes over at entry point)
  - If error: returns negative, old image still running (can retry)

### Userspace Layer (New Implementation)

#### 1. shell_exec.h - Syscall Wrappers
Provides inline assembly wrappers for V2_INV_* operations:
- `shell_spawn(idx)` → syscall → child tid
- `shell_fork()` → syscall → child tid (parent) / 0 (child)
- `shell_exec(idx)` → syscall → never returns (success) / -err (failure)

**Design**: Thin layer over ecall V2_INVOKE; direct 1:1 mapping to kernel.

#### 2. initrd_vfs.h - Program Discovery
Abstract interface to initrd metadata:
- `initrd_find_program(name)` → initrd index
- `initrd_get_size(idx)` → size in bytes
- `initrd_is_loadable(idx)` → bool (basic validation)
- `initrd_list_programs(callback)` → iterate all programs

**Metadata**: Hardcoded table (generated by tools/mkinitrd.sh at build time):
```
Index 0: mem_server.elf (kernel service)
Index 1: qrexec_server.elf (broker)
Index 2: adminvm.elf (broker)
...
Index 8: hello.elf (test program)
Index 9: cat.elf (utility)
Index 10: echo.elf (utility)
Index 11: ls.elf (utility)
```

#### 3. shell_programs.h - Program Launcher API
High-level command execution interface:
- `shell_lookup_program(name)` → initrd index
- `shell_spawn_program(name)` → child tid (SPAWN)
- `shell_fork_and_exec_program(name)` → child tid (parent) / replaces self (child)
- `shell_exec_program(name)` → never returns (EXEC)
- `shell_list_programs(callback)` → iterate discovered programs

**Design Patterns**:

1. **SPAWN for background jobs**:
   ```c
   int child = shell_spawn_program("hello");
   if (child > 0) {
       // Shell continues, child runs independently
       shell_puts("Started hello as task ");
       shell_print_ulong(child);
   }
   ```

2. **FORK+EXEC for command execution (classic Unix)**:
   ```c
   int child = shell_fork_and_exec_program("cat");
   if (child > 0) {
       // Parent: wait for child, then continue
       shell_wait_child(child, NULL);
   }
   // Child: replaced with cat.elf image, never returns here
   ```

3. **Direct EXEC for exec chains**:
   ```c
   shell_exec_program("bash");
   // Never reaches here (bash takes over)
   ```

#### 4. shell.c Integration
Shell command dispatcher enhanced with:
- Program discovery in help system ("help" lists all discoverable programs)
- "exec <name>" builtin: calls `shell_fork_and_exec_program()`
- "spawn <name>" builtin: calls `shell_spawn_program()`
- Background job tracking (future: wait/fg/bg)

**Command Examples**:
```
moonsh> help               # Lists builtins + discovered programs
moonsh> exec hello         # Fork shell, exec hello.elf
moonsh> spawn cat file.txt # Spawn cat in background
moonsh> ps                 # List threads (can see spawned children)
moonsh> kill <tid>         # Terminate child thread
```

- `hello_main.c`: Minimal test program

  - Builds as hello.elf

## VSpace Layout for User Programs

Each new thread gets its own three-level Sv39 page tables:

```
root_pt_t[tid]
├── [0] → l1_m (shared UART megapage, all threads)
└── [2] → l1_t[tid] (per-thread)

l1_t[tid]
├── [1] → l0_k (shared kernel image, RX, all threads)
├── [4] → l0_u_t[tid] (user frame window, 2MB at 0x80800000)
├── [8] → l0_frames (shared frame pool, S-only identity map)
└── [other] → specialized MMIO (NET, BLK, RNG, GUI for specific tids)

l0_u_t[tid]
├── [0-31] → frames (32 VPN slots × 4KB = 128KB user memory)
```

**Key**: Each thread has its own `l0_u_t[tid]` (user frame window). The frame pool (`l0_frames`) is shared S-only, so the kernel can load ELF bytes and COW-break pages without exposing the pool to user code.

## Capability Model for Programs

Each thread has a 32-slot capability table (`caps[tid][0-31]`):
- **Slots 0-X**: Frame capabilities (obj = frame id, rights = R/W/X)
- **Root caps** (set only for initial threads): Allow minting new capabilities
- **Rights**: R (read), W (write), X (execute), W^X (never both write+execute together)

**Frame Lifecycle**:
1. ELF load allocates frames (kernel authority via SPAWN/FORK/EXEC)
2. Frame caps created with R/W/X appropriate to segment (X for .text, W for .data)
3. Mappings created via MAP syscall: cap rights → PTE flags
4. On exec: old frames freed, new frames allocated
5. On fork: frames shared initially, COW-broken on write

## Error Handling

**SPAWN Failures**:
- Program not found: return -ENOENT
- No free thread slots: return -EAGAIN (all 11 threads busy)
- ELF validation fails: return -EINVAL (bad magic, W+X, overlap, etc.)
- Frame pool exhausted: return -ENOMEM (< 32 free frames)
- Page table full: return -ENOSPC (mappings table exhausted)

**FORK Failures**:
- No free thread slots: return -EAGAIN
- Cap table copy fails: return -ENOMEM

**EXEC Failures**:
- Program not found: return -ENOENT
- ELF validation fails: return -EINVAL
- Old image preserved on failure; can retry or try different program

**Shell Handling**: Commands that fail display error message and return to prompt:
```
moonsh> exec nonexistent
Error: program not found (-1)
moonsh>
```

## Future Enhancements

1. **Interactive Program Execution**:
   - STDIN/STDOUT redirection (currently uses shared V2_PUTC/GETC)
   - Pipes: spawn(cat) | spawn(grep) via IPC

2. **Job Control**:
   - bg/fg commands (move jobs between background/foreground)
   - Proper wait() implementation with exit codes
   - Signal handling (SIGKILL via kill syscall, SIGSTOP/SIGCONT)

3. **VFS Integration**:
   - Access files outside initrd (dynamic loading)
   - Script execution (if file contains shell commands)

4. **COW Optimization**:
   - Lazy COW break (only on actual write fault, not FORK time)
   - Already implemented: fault handler does the break

5. **Program Arguments**:
   - Pass argv[] to spawned programs via shared memory or IPC
   - execve(path, argv) syscall (currently no argv support)

## Summary

The implementation provides a **complete ELF execution system**:

1. **Kernel**: SPAWN, FORK, EXEC syscalls with full VSpace building, ELF loading, COW semantics
2. **Userspace**: Command discovery, program launcher API, shell integration
3. **Testing**: Hello world test program + shell commands to spawn/exec it
4. **Design**: Fail-closed validation, all-or-nothing ELF load, per-thread capability isolation

Users can now:
- Run shell commands: `exec hello`, `spawn cat`, etc.
- Discover available programs: `help` command
- Background tasks: `spawn prog &` (simple version)
- Chain programs: `exec prog1 && exec prog2` (though unusual in single-threaded context)

This enables a **usable command-line environment** for MoonlightOS QEMU virtual machine, with extensibility for future features (pipes, redirection, scripting).
