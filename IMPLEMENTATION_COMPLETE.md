## What Was Accomplished

### ✅ Kernel Layer (Tasks 1-4)
**Status**: ALREADY IMPLEMENTED - No changes needed

The kernel (`kernel/kboot.c`) provides three production-quality syscalls:

1. **V2_INV_SPAWN (9)** - Create thread + load ELF
   - Finds free T_DEAD slot
   - Builds per-thread VSpace (page tables, kernel/frames/user windows)
   - Loads ELF from initrd (validation → frame allocation → byte copy → PTE sync)
   - All-or-nothing: any error rolls back all resources
   - Returns child tid

2. **V2_INV_FORK (10)** - Duplicate VSpace (Copy-on-Write)
   - Copies parent's capabilities and mappings
   - Applies COW write protection (drops PTE_W from both sides)
   - Fault handler: allocates new frame on write, updates only faulting thread
   - Returns child_tid to parent, 0 to child (standard fork semantics)

3. **V2_INV_EXEC (11)** - Replace image (execve-like)
   - Unmaps all user mappings, frees frames
   - Clears user capabilities (keeps root caps)
   - Loads new ELF into same thread
   - On success: never returns (new image takes over)
   - On error: returns -1, old image preserved

## Key Design Decisions

### 1. Userspace-Kernel Split
- **Kernel**: Low-level process model (SPAWN/FORK/EXEC) + memory management
- **Userspace**: High-level discovery and launcher API
- **Benefit**: Clean separation, kernel can't be bloated with discovery logic

### 2. Hardcoded Program Table
- **Approach**: shell_programs.h with static {name, index} entries
- **Generated by**: tools/mkinitrd.sh at build time
- **Benefit**: Zero-copy lookup, simple implementation, clear dependencies

### 3. Copy-on-Write for FORK
- **Why**: Avoid frame duplication overhead
- **How**: PTE_W dropped from both parent/child, fault handler breaks on write
- **Benefit**: Efficient fork even with large program images

### 4. All-or-Nothing ELF Load
- **Why**: No half-loaded states (security + simplicity)
- **How**: If any validation fails, rollback all allocated frames/caps/mappings
- **Benefit**: Consistent system state, no resource leaks

### 5. Fail-Closed Syscalls
- **Why**: Any validation error returns negative, state unchanged
- **How**: Checked-then-acted pattern (check, allocate, commit)
- **Benefit**: Safe error recovery, no corrupted kernel state

## Architecture Overview

### VSpace Per Thread
```
root_pt_t[tid]
├── [0] → shared UART (all threads)
└── [2] → l1_t[tid] (per-thread)

l1_t[tid]
├── [1] → shared kernel image (RX)
├── [4] → l0_u_t[tid] (user frame window, 2MB)
├── [8] → shared frame pool (S-only)
└── [other] → specialized MMIO for specific tids

l0_u_t[tid][32]
├── [0-31] → user frames (1 frame per slot, 128KB max)
```

### Capability Model
- Per-thread cap table: 32 slots × frame capability
- Rights: R (read), W (write), X (execute), W^X enforced
- Mappings: per-thread, 32 VPN slots per thread
- Authority: kernel allocates, attenuates on MINT/GRANT/MAP

### Process Model
- Fixed 11 threads max (T_RUNNABLE, T_BLOCKED, T_PARKED, T_DEAD)
- Thread reuse: T_DEAD slots can be recycled via SPAWN
- 40 frames in pool (160KB total user memory for MVP)
- Per-thread stack pointer pre-fetched pre-MMU

```
moonsh> ps                       # List threads

```

### C API Usage
```c
// Spawn background job
int child_tid = shell_spawn_program("hello");

// Fork+exec (classic pattern)
int child = shell_fork_and_exec_program("cat");
if (child > 0) {
    // Parent: wait for child...
    shell_wait_child(child, NULL);
} else if (child == 0) {
    // Should not reach (child image replaced)
} else {
    // Error
}

// Direct exec (shell replacement)
shell_exec_program("bash");  // Never returns
```

## Security Properties

### Memory Isolation
- Each thread has isolated VSpace (no buffer overflow access across threads)
- Frame pool identity-mapped S-only (no user access to pool metadata)
- PTE_W^X enforced (no writable code execution)

### Capability Gating
- SPAWN/FORK/EXEC only in kernel (user cannot allocate threads)
- ELF loading validated before any allocation (fail-closed)
- Memory rights checked on every MAP/UNMAP/READ/WRITE

### Attack Surface
- ELF validator runs on untrusted input (validated before any modification)
- All syscalls range-check before dereferencing (SUM=0 except copy windows)
- No TOCTOU races (validate-then-act atomic in syscall context)
